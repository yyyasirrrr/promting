Chapter 01

Introduction to Prompt Engineering

Big idea: A language model produces a continuation of the information it receives. Prompt engineering is the practice of making that continuation useful, relevant, and reliable.

⏱ ~10 min read 🎯 Focus: History, Attention, Transformers, Prompt Design
01 / The starting point

The Central Question

What makes a model's next words useful for a particular task?

“The most important discovery of the experiment was…”

The same opening can lead to a scientific report, a dramatic story, or a short summary. The words surrounding the request determine which kind of continuation is likely.

Prompt engineering means designing instructions, examples, and context so that the output serves a purpose. In an application, it also includes deciding what information to retrieve, how to structure a conversation, and how to use the result.

01

Instructions

Describe the task, target audience, constraints, and desired behavior.

02

Context

Provide the relevant facts, examples, documents, and conversation history.

03

Output

Specify a useful format (JSON, markdown, table) and plan how to verify the result.

01 / Origins

How Did We Get Here?

Modern conversational assistants grew out of successive solutions to information-processing problems.

  1. 1940s+
    Statistical language models & Markov chainsPredict text from a limited preceding context using statistical transition probabilities.
  2. 2014
    Sequence-to-sequence (seq2seq) modelsAn encoder and decoder transform one sequence into another, such as in machine translation.
  3. 2015
    Attention in neural sequence modelsThe decoder can consult relevant parts of its input instead of relying on one compressed summary.
  4. 2017
    The Transformer ArchitectureAttention becomes the central mechanism for relating positions in a sequence without recurrence.
  5. 2018
    GPT (Generative Pre-trained Transformer)A transformer-based text generator is broadly pre-trained on massive text, then adapted to useful tasks.
  6. GPT-2 → 4
    Increasingly capable foundation modelsPrompting becomes a practical way to perform tasks without training a new model for each one.

Key takeaway: The transition was not from "predicting words" to an entirely different principle. It was from simple predictions with limited context to powerful, context-sensitive prediction.

01 / The Bottleneck

A Sentence Is Not a Single Vector

Early translation systems attempted to squeeze an entire input sequence into a single fixed-size representation.

Source sentence→Encoder→Compressed "Thought Vector"→Decoder→Translation

This works for short inputs. But an entire paragraph contains names, qualifications, and relationships that cannot all fit cleanly into one small summary. Details vanish before the decoder finishes.

Attention Changes the Picture

With attention, the decoder can consult multiple representations of the source words. At each output step, it gives more weight to the parts that matter for the next token.

Without Attention (Bottleneck)

  • One summary vector carries all input information.
  • Details disappear in long sequences.
  • Fixed-size representation creates an information bottleneck.

With Attention (Dynamic Access)

  • Decoder directly consults a collection of source representations.
  • Different source words matter at different output steps.
  • Relevant context is accessible when needed.
01 / The Architecture

Attention Becomes the Architecture

The 2017 paper Attention Is All You Need removed recurrence entirely, using attention to connect token positions directly.

G

Generative

Produces new text continuations by estimating next-token probability distributions.

P

Pre-trained

Learns broadly from billions of tokens of diverse text before adapting to specific tasks.

T

Transformer

Uses layered self-attention to process relationships across the entire context simultaneously.

Text generation in GPT-style models is autoregressive: the model calculates the probability of the next token given all preceding tokens:

P(tn+1 | t1, t2, …, tn) Probability of token tn+1 given context sequence t1…tn

01 / Reality Check

Three Limitations Worth Remembering

Not a Search Engine

A model produces plausible text without natively checking or retrieving authoritative sources.

Finite Context Window

It can only process content fitting within its supported token limit. Curation is mandatory.

Fluency Is Not Accuracy

A well-written, confident answer can still contain factual or logical errors.

Check Your Understanding

Why was one "thought vector" problematic for long inputs?

It forced the entire sequence into a single fixed-size representation. Important qualifiers, names, and relationships in earlier parts of the text were often overwritten or lost before decoding finished.

What changes when the decoder uses attention?

At every output step, the decoder can consult multiple source representations, placing higher attention weights on the specific source words that are relevant to generating the next token.

What makes "Explain transformers" a weak prompt?

It lacks an intended audience, scope boundaries, sequencing order, structural format requirements, and constraints on technical terminology.

Chapter 02

Understanding How Language Models Work

Big idea: To use a language model well, understand what it actually processes: tokens, probability distributions, and context. Many prompting mistakes become easy to diagnose once these three ideas are clear.

⏱ ~17 min read 🎯 Focus: Tokenization, Generation Loop, Temperature, Self-Attention, Hallucinations
02 / Architecture

The Whole Mechanism in One Picture

A simplified GPT-style generation loop operates through a cyclic pipeline:

Input Text→Tokenizer→Token Representations→Causal Transformer→Logit Scores→Sample/Select→Append Token↺

Crucial realization: Nothing in this loop directly guarantees factual truth. The model learns statistical and semantic patterns during training, then applies those patterns to select the next token under the current prompt context.

02 / Foundations

A Language Model Continues a Sequence

A base model is fundamentally a text-completion engine. Given the prefix:

“Yesterday, my TV stopped working. Now I can't turn it on at…”

The most probable next word is “all.” But after that, the continuation could diverge into a personal anecdote, an angry review, or a technical repair guide. The prompt does not merely state a topic—it establishes an expectation about the document type that should follow.

02 / Representation

Tokens: The Model's Units of Text

Humans see words and characters. Language models operate on numerical token IDs.

Human-Readable TextTypical Tokenization Behavior
catSingle whole-word token.
unbelievableSplit into multiple subword tokens (e.g. un + believ + able).
Punctuation (., ,)Often its own individual token.
Uncommon spellings or codeBroken into smaller subwords or individual character tokens.
Spacing and capitalizationAlters token IDs completely (e.g., Apple vs apple).

Three Practical Consequences

01

Character Tasks

Anagrams, letter counts, and reverse spelling are challenging because the model doesn't see individual letters by default.

02

Formatting Costs

Markdown formatting, code fences, indentation, and repeated delimiters consume valuable token budget.

03

Language Variation

Non-English languages often require significantly more tokens for the exact same sentence length.

02 / Constraints

The Context Window Is Finite

The context window holds everything the model can consider at once: system instructions, chat history, retrieved documents, and room for the completion.

Include First (Essential)Include Only if RelevantUsually Remove (Waste)
Task goal and desired output formatRepresentative solved examplesRepeated system instructions
Essential facts, schemas, and constraintsPrior conversation turnsUnrelated background essays
Direct source excerpts needed for accuracyStyle demonstrationsRedundant boilerplate passages
02 / Generation

Autoregression: One Token at a Time

Generation is strictly sequential. The model does not compose an entire paragraph and then display it; each new token is appended to the context and fed back into the next step:

The→cat→sat→on→the→[mat]→[.]

Early Choices Matter

A poor initial phrase steers all subsequent token predictions into an unhelpful direction.

Repetition Reinforces Itself

Once a repetitive loop appears in the text, autoregression makes repeating the loop statistically likely.

02 / Sampling

Logits, Softmax & Temperature

For every position, the model computes raw numerical scores (logits) across its vocabulary. The softmax function converts logits into a normalized probability distribution.

pi(T) = exp(zi / T) / ∑j exp(zj / T) zi is the logit for token i; T is the sampling temperature.
Candidate TokenIllustrative ProbabilityDecoding Role
mat52%Top candidate (Greedy decoding selects this).
sofa28%Plausible alternative (Sampled occasionally at T > 0).
floor15%Plausible alternative.
moon5%Unlikely candidate (Sampled only at high T).

Temperature Guidelines

Temperature RangeBest Task TypesBehavior & Trade-offs
0.0 – 0.3Factual extraction, code generation, JSON parsingHighly predictable, consistent phrasing. Does NOT guarantee truth.
0.5 – 0.8General writing, dialogue, explanationsBalanced variety in tone and vocabulary while staying coherent.
0.9 – 1.3Creative ideation, brainstorming, roleplayHigh diversity of ideas; increased risk of drifting off-topic.
Above 1.3Experimental generationChaotic, often grammatically fragmented and erratic.

Crucial distinction: Low temperature makes an answer more predictable, not necessarily more accurate.

Self-attention allows tokens to communicate dynamically across layers using Query, Key, and Value vectors.

02 / Latency & Cost

Reading vs Writing Have Different Costs

Prefill Phase (Prompt Processing)

The input prompt tokens are evaluated in parallel across GPU tensor cores. Highly compute-efficient.

Decode Phase (Token Generation)

Each output token is generated sequentially. Memory-bandwidth bound; dominates latency.

02 / Reliability

Hallucinations: When Fluent Text Is Wrong

A hallucination is an output containing unsupported, invented, or false claims presented with complete fluency.

Type of HallucinationExample Failure Mode
FactualInventing dates, biographical details, or chemical formulas.
LogicalDrawing conclusions that directly contradict the provided prompt premises.
StructuralGenerating convincing URLs, document titles, or API endpoints that do not exist.

Five Practical Defenses

  1. Supply trustworthy sources: Ground the prompt in verified reference material.
  2. Provide a fallback instruction: Explicitly state what to do if the context doesn't contain the answer (e.g., “State that the information is unknown”).
  3. Use tool retrieval: Fetch live facts via APIs or search rather than relying on parametric memory.
  4. Verify outside prose: Test code with interpreters, parse JSON with schemas, check links with HTTP requests.
  5. Decompose tasks: Break complex problems into smaller, verifiable steps.
02 / Review

Chapter 2 Recap & Understanding Checks

Core axiom: Tokens are not words. Probabilities are not facts. Fluency is not verification.

Check Your Understanding

Why might simple character counting be hard for an LLM?

Because the tokenizer groups sequences of characters into subword token IDs. The model processes token IDs rather than individual letters, making exact letter counting an indirect inference task.

How do greedy decoding and sampling differ?

Greedy decoding always selects the token with the highest logit score at every step (deterministic). Sampling draws randomly from the probability distribution, introducing variation across runs.

What does causal masking prevent?

It hides future token positions during generation so each token only attends to preceding context, preserving strict left-to-right autoregressive prediction.

Chapter 03

Chat Models, Human Feedback, and Tools

Big idea: A base model can complete text. A chat assistant is a language model trained and packaged to participate in a structured conversation, follow instructions, and cooperate with tools.

⏱ ~15 min read 🎯 Focus: SFT, RLHF, Message Roles, ChatML, Sampling Parameters, Tool Execution
03 / Evolution

From “Continue This Text” to “Help Me With This Task”

Suppose we present an LLM with: What is a good indoor activity for a family of four?

A base model might continue this as a questionnaire, a forum thread, or a list of queries. What the user actually wants is an answer. This mismatch drove the evolution from base models to conversational assistants.

Model TypeTypical BehaviorMain Challenge
Base ModelCompletes raw text based on internet corpus statistics.May continue the document format rather than answering the query.
Instruction-TunedTrained on supervised task-response pairs.Lacks a formal multi-turn structure for dialogue context.
Chat ModelUnderstands distinct message roles (System, User, Assistant, Tool).Still requires external grounding, careful prompting, and safe tool gating.
03 / Alignment

The HHH Alignment Standard

Base models learn everything in their training corpus—both brilliant tutorials and toxic arguments. Alignment steers behavior toward three core objectives:

H

Helpful

Directly addresses the user's legitimate goals with clarity, relevance, and appropriate depth.

H

Honest

Avoids fabricating facts, cites sources accurately, and expresses calibrated uncertainty when unknown.

H

Harmless

Refuses malicious requests (malware, exploits, harm) while minimizing false refusals.

03 / The Pipeline

The Alignment Training Pipeline: SFT → RM → RLHF

Pre-trained Base Model→Supervised Fine-Tuning (SFT)→Human Preference Comparison→Reward Model (RM)→PPO Policy Optimization→Aligned Assistant
A

Stage A: SFT

High-quality demonstration datasets teach the model the conversational structure of a helpful assistant.

B

Stage B: Preferences

Human annotators compare multiple model responses to rank which one is clearest and most accurate.

C

Stage C: Reward Model

A separate model learns to predict human preference scores across thousands of comparison pairs.

D

Stage D: RL (PPO)

Reinforcement learning optimizes the generator policy to maximize reward scores without collapsing into gibberish.

Reward Hacking Warning: The reward model is a mathematical approximation of human taste. If unconstrained, the model may optimize for long-winded, flattering prose that scores well on the reward model without actually being accurate.

03 / Trade-offs

Benefits & Trade-offs of RLHF

Benefits

  • Follows multi-step user instructions with high fidelity.
  • Polite and calibrated refusal of dangerous requests.
  • Appropriate conversational tone for general audiences.

Trade-offs & "Alignment Tax"

  • Preference bias: Annotator demographics affect model style.
  • Alignment tax: Optimization can slightly degrade creative flexibility or coding precision.
  • Superficial agreeableness: Tendency to agree with user premises even when wrong ("sycophancy").
03 / Dialogue Structure

Chat Messages Have Roles & ChatML

A modern chat API is not a raw string; it is a structured array of role-delimited messages.

RolePrimary FunctionTypical Content
systemSets foundational persona, behavioral guardrails, and tool rules."You are an expert code reviewer. Be concise and suggest diffs."
userThe human request, question, or follow-up."How do I fix this React hydration error?"
assistantResponses generated by the model (or tool call requests)."The hydration error occurs because server and client HTML differ..."
toolStructured outputs returned by an external API or database call.{"status": "success", "rows_found": 3}

ChatML Representation

Behind the API, special boundary tokens delineate messages to prevent the model from confusing instructions with conversational history:

ChatML Token Format Concept
<|im_start|>system
You are a concise technical support assistant.
<|im_end|>
<|im_start|>user
Explain the difference between RAM and SSD storage.
<|im_end|>
<|im_start|>assistant
RAM provides high-speed volatile working memory for active tasks; SSD provides persistent non-volatile long-term data storage.
<|im_end|>

Security Note: While role boundaries separate messages, they do not guarantee immunity against indirect prompt injection. Any content ingested from websites or tools must be treated as untrusted.

Parameters Behind a Chat Response

03 / Tool Calling

Extending Conversations with Tools

An LLM cannot directly connect to a database or execute bash commands. An application provides tool definitions (JSON schemas), letting the model request actions.

User asks question→Model requests tool call→Application executes API→Tool result sent to model→Model synthesizes answer

Read-Only Tools

Search documentation, query read-only database replicas, fetch train timetables, check server health. Low risk.

Write-Capable Tools

Send emails, charge credit cards, delete cloud buckets, modify git repositories. Requires user confirmation & strict authentication.

03 / In Practice

Writing Operational System Instructions

An effective system prompt defines five key boundaries:

Operational Technical Support Prompt
You are a technical support assistant for non-technical users.
Use only the documentation provided in the conversation context.
Provide no more than five numbered troubleshooting steps in sequence.
If the supplied documentation does not contain an answer, state: "I cannot find this in our documentation."
Do not claim any system settings were changed unless a verified tool confirmation was received.
03 / Review

Chapter 3 Recap & Understanding Checks

Check Your Understanding

Why might a base model continue a question with another question?

Because in raw text corpora, questions frequently appear in FAQ lists, exam papers, or interview questionnaires. The base model completes the statistical document pattern rather than assuming an assistant role.

Who actually runs the tool code: the model or the application?

The application runs the code. The model only produces a structured JSON string requesting the function call with specific argument parameters. The application validates, authenticates, and executes the call.

What are the three pillars of HHH alignment?

Helpful (delivering what the user requested), Honest (grounded in evidence, transparent about limits), and Harmless (refusing dangerous or destructive actions).

Chapter 04

Designing Applications with Language Models

Big idea: The model produces text; the application turns a real-world problem into the right model input and turns the output into a useful result. Good applications are built around this transformation.

04 / Framework

Think in Loops, Not Isolated Prompts

A prompt is a single API call; an LLM application is an end-to-end transformation process.

User Goal→Application Preparation→Assembled Context + Prompt→LLM Generation→Validate / Act→Result to User

User Domain

Business problems, appointments, files, user preferences, buggy code, real-world constraints.

Model Domain

Tokenized strings, role messages, attention scores, temperature sampling, generated tokens.

04 / Prompt Design

Four Requirements of an Effective Prompt

1

Familiar Format

Frame the prompt in a recognizable genre (diagnostic plan, diff, table).

2

Sufficient Info

Supply necessary observations while discarding irrelevant clutter.

3

Clear Direction

Instruct the model on what specific task to execute first.

4

Stopping Point

Define an explicit stopping boundary (e.g. "at most 5 steps").

Weak Prompt
My computer is slow. Help.
Operational Prompt
# Goal: Create a safe diagnostic plan for a slow Windows 10 PC.
# Observations:
- Performance dropped 3 days ago following an OS update.
- Browser, code editor, and chat app are usually open.
- Fan noise is louder than normal.
# Requirements:
- Suggest at most 5 safe diagnostic steps (Task Manager, disk space, temperatures).
- Explain briefly what each observation might indicate.
- Do not suggest registry edits or destructive reinstalls.
04 / Pipeline

The Feedforward Context Pipeline

Before calling the model, an application runs a four-stage feedforward preparation sequence:

Pipeline StageAction PerformedConcrete Example
1. RetrievalFetch candidate data from database, vector index, or files.Read support KB article #412 on fan diagnostics.
2. SnippetizationExtract manageable excerpts from large documents.Cut the 20-page manual down to the CPU temperature section.
3. PrioritizationScore and rank excerpts to fit within the token budget.Put Windows 10 specific fixes ahead of general macOS tips.
4. AssemblyCombine system boilerplate, ranked context, and user prompt.Construct the final JSON payload for the API endpoint.
04 / Context Policy

Context Budget Policy

More context is not always better. The "Lost in the Middle" phenomenon shows that models attend best to the beginning and end of long contexts. Apply a strict selection policy:

  • Relevance: Does this snippet directly answer the user's immediate question?
  • Freshness: Has this information been superseded by a more recent user action?
  • Deduplication: Are multiple passages repeating the exact same factual claim?
  • Token cost: Does this document justify its compute and latency footprint?
04 / Model Selection

Choosing a Model Is an Engineering Decision

04 / Execution

Output Handling: Proposal vs Action

Separation of Concerns: Never let a model directly execute side effects. The model produces a proposed intent; the application validates the schema, verifies user permissions, checks safety constraints, and executes the action.

04 / Persistence

Stateful Conversations & RAG

Long conversations degrade if the entire raw transcript is repeatedly sent. Stateful applications track a structured session state:

Structured State Record
{
  "user_goal": "Troubleshoot overheating laptop",
  "confirmed_facts": ["OS: Windows 10", "Fan runs at 100% idle"],
  "attempted_steps": ["Checked Task Manager - CPU at 95% from searchindexer.exe"],
  "pending_action": "Rebuild Windows search index"
}
04 / Agents

ReAct: Reasoning + Acting Loops

ReAct interleaves thinking and external actions in a cyclical decision loop:

Thought (What do I need?)→Action (Call tool API)→Observation (Inspect response)→Repeat or Final Answer
04 / Testing

Offline vs Online Application Evaluation

Evaluation TypeMethodologyKey Metrics
Offline (Pre-release)Run curated benchmark suites of test prompts against golden references.Factual accuracy, JSON schema validity, unit test pass rate, latency.
Online (In production)Monitor telemetry, user interactions, and implicit behavioral signals.Acceptance rate of suggested code, thumbs up/down, task completion rate.
04 / Review

Application Design Checklist

  • An LLM application is an end-to-end transformation loop, not just a prompt.
  • Context retrieval, snippet filtering, and prompt assembly belong to the application code.
  • Separate model proposals from external action execution.
  • Track structured state rather than unbounded chat transcripts.
  • Evaluate end-to-end task success, not just convincing prose.
Chapter 05

Prompt Content, Context, and Retrieval-Augmented Generation

Big idea: The quality of an LLM response depends not only on the instruction, but also on which information enters the prompt. The engineering challenge is to find, prioritize, and present the most useful context.

⏱ ~22 min read 🎯 Focus: Static vs Dynamic Content, Zero/Few-Shot, Embeddings, Jaccard vs Cosine, RAG Pipelines, Failure Modes
05 / Case Study

The Context Problem: Recommending a Book

Imagine an assistant receives only: My last three books were A, B, and C. What should I read next?

It generates generic answers. Now imagine the application also supplies that the reader loves historical fiction, dislikes self-help books, prefers shorter novels, and recently enjoyed stories set in South America.

The recommendation task has not changed. The available context has. The prompt engineering bottleneck is rarely phrasing; it is information assembly.

05 / Classification

Dynamic ContextUser profile, recent interactions, live retrieved excerpts.Changes every single request."User completed a sci-fi novel 2 hours ago."
Complete Grounded Prompt Blueprint
# Task
Recommend three books for leisure reading based on the user's history.

# General Instructions

# User Context (Dynamic)

Dislikes: self-help books, books longer than 400 pages.

# Output Format

05 / Demonstrations

Zero-Shot vs Few-Shot Prompting

Zero-Shot Prompting

Provides only the task instruction without examples.

Classify sentiment as positive, neutral, or negative:
Text: "It was fine, but not especially memorable."
Sentiment:

Few-Shot Prompting

Includes solved demonstrations to lock in formatting & nuance.

Text: "An excellent experience." -> Sentiment: positive
Text: "The service was terrible." -> Sentiment: negative
Text: "It was fine, but not memorable." -> Sentiment: neutral

Two Dangerous Failure Modes in Few-Shot Prompting

Scaling Failure

Adding too many examples crowds the context window, causing the model to confuse demonstration boundaries with the active task.

Anchoring Bias

The model mimics the distribution of demonstrations. If 3 out of 3 examples are "positive", it will heavily favor predicting "positive".

05 / Discovery

Context Mapping & Scoring

Before writing code, map out candidate sources like branches of a tree (Reading history, Preferences, Personal goals, Availability). Then score each candidate:

  • Relevance: Does it directly answer this query?
  • Reliability: Is it from an authoritative document?
  • Supersession: Does an explicit user statement invalidate an inferred preference?
05 / RAG

Retrieval-Augmented Generation (RAG)

RAG bridges private or changing data with generative fluency. Chekhov's Gun Principle: If an irrelevant fact enters the prompt, the model will often force it into the answer. Better retrieval beats longer prompts.

05 / Search Types

Lexical Retrieval & Jaccard Similarity

Lexical search matches exact terms. The Jaccard coefficient calculates word overlap:

J(A, B) = |A ∩ B| / |A ∪ B| Ratio of shared words to total unique words between query A and passage B.

Example: Query terms = {space, travel, novel} (3 words). Passage terms = {space, travel, novel, science} (4 words). Intersection = 3, Union = 4. J = 3/4 = 0.75.

Strengths: Exact product IDs, error codes, zero hallucination of terms. Weakness: Vocabulary mismatch (fails on synonyms like "automobile" vs "car").

05 / Embeddings

Neural Retrieval & Cosine Similarity

Neural search maps text into high-dimensional embedding vectors where semantically similar texts lie close together.

cosim(a, b) = (a · b) / (||a|| ||b||) Cosine of the angle between vector embeddings a and b.

Lexical (BM25 / Keyword)

  • Exact keyword and serial number matching.
  • Zero embedding computation overhead.
  • Transparent and easy to audit.

Neural (Dense Vector Search)

  • Handles paraphrases, synonyms, and multilingual queries.
  • Requires embedding models and vector indexes (FAISS, Milvus).
  • May retrieve conceptually related but factually wrong passages.
05 / Chunking

Snippetizing & Sliding Windows

Large documents must be chunked into coherent excerpts with overlap so context is not sliced across boundaries:

Python Chunking with Overlap (Sliding Window)
def snippetize(text: str, window_words: int = 200, stride_words: int = 120) -> list[str]:
    words = text.split()
    chunks = []
    for start in range(0, len(words), stride_words):
        chunk = words[start : start + window_words]
        if not chunk: break
        chunks.append(" ".join(chunk))
        if start + window_words >= len(words): break
    return chunks

05 / Review

Chapter 5 Recap & Understanding Checks

Golden Rule: Don't just ask "How should I phrase the prompt?" Ask "What information must enter this prompt, where will it come from, and how will I know it is correct?"

Check Your Understanding

Why must the query embedding model match the document embedding model?

Embedding models map language into custom mathematical coordinate spaces. Using different models places the query and documents into completely incompatible spaces, destroying similarity scoring.

What does the stride of a sliding window control?

The stride determines how far the window shifts forward between consecutive chunks. The difference between the window size and the stride defines the word overlap (e.g., window 200 - stride 120 = 80 words overlap).
